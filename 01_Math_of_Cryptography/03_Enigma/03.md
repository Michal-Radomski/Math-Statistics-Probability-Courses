You can absolutely simulate the **Enigma machine** in **TypeScript (TS)**, including both encryption and decryption of
strings.

The Enigma machine is actually a great project for TypeScript because its encryption process is based on:

- Rotor permutations.
- Rotor stepping (rotational movement).
- Reflector mappings.
- Plugboard substitutions.
- Configurable rotor positions and ring settings.

## 1\. How Enigma encryption works

The encryption process follows this path:

text

```text
Plaintext character
       |
       v
    Plugboard
       |
       v
   Rotor III
       |
       v
    Rotor II
       |
       v
    Rotor I
       |
       v
   Reflector
       |
       v
    Rotor I (reverse)
       |
       v
   Rotor II (reverse)
       |
       v
   Rotor III (reverse)
       |
       v
    Plugboard
       |
       v
Encrypted character
```

Before processing each character, the rotors rotate according to the Enigma stepping mechanism.

## 2\. TypeScript implementation

Here's a simplified but functional Enigma simulator using three rotors and a reflector.

Enigma Machine Simulator in TypeScript

typescript

```typescript
const alphabet = "ABCDEFGHIJKLMNOPQRSTUVWXYZ";

const ROTORS = {
  I: {
    wiring: "EKMFLGDQVZNTOWYHXUSPAIBRCJ",
    notch: "Q",
  },
  II: {
    wiring: "AJDKSIRUXBLHWTMCQGZNPYFVOE",
    notch: "E",
  },
  III: {
    wiring: "BDFHJLCPRTXVZNYEIWGAKMUSQO",
    notch: "V",
  },
};

const REFLECTOR = "YRUHQSLDPXNGOKMIEBFZCWVJAT";

class Enigma {
  private positions = [0, 0, 0];

  constructor(
    private rotors: string[] = ["I", "II", "III"],
    initialPositions: string = "AAA"
  ) {
    this.positions = [...initialPositions].map((char) => alphabet.indexOf(char));
  }

  private rotate() {
    // Simplified stepping mechanism
    this.positions[2] = (this.positions[2] + 1) % 26;

    if (this.positions[2] === 0) {
      this.positions[1] = (this.positions[1] + 1) % 26;
    }

    if (this.positions[1] === 0) {
      this.positions[0] = (this.positions[0] + 1) % 26;
    }
  }

  private forward(index: number, rotor: string, position: number): number {
    const wiring = ROTORS[rotor as keyof typeof ROTORS].wiring;

    const shifted = (index + position) % 26;
    const mapped = alphabet.indexOf(wiring[shifted]);

    return (mapped - position + 26) % 26;
  }

  private backward(index: number, rotor: string, position: number): number {
    const wiring = ROTORS[rotor as keyof typeof ROTORS].wiring;

    const shifted = (index + position) % 26;
    const mapped = wiring.indexOf(alphabet[shifted]);

    return (mapped - position + 26) % 26;
  }

  private encryptCharacter(char: string): string {
    let index = alphabet.indexOf(char);

    if (index === -1) return char;

    this.rotate();

    // Forward through rotors
    for (let i = 2; i >= 0; i--) {
      index = this.forward(index, this.rotors[i], this.positions[i]);
    }

    // Reflector
    index = alphabet.indexOf(REFLECTOR[index]);

    // Backward through rotors
    for (let i = 0; i < 3; i++) {
      index = this.backward(index, this.rotors[i], this.positions[i]);
    }

    return alphabet[index];
  }

  encrypt(text: string): string {
    return [...text.toUpperCase()].map((char) => this.encryptCharacter(char)).join("");
  }
}

// Encryption
const machine = new Enigma(["I", "II", "III"], "AAA");

const encrypted = machine.encrypt("HELLOWORLD");

console.log("Encrypted:", encrypted);

// Decryption
const decryptMachine = new Enigma(["I", "II", "III"], "AAA");

const decrypted = decryptMachine.encrypt(encrypted);

console.log("Decrypted:", decrypted);
```

## 3\. Why encryption and decryption use the same function

One interesting property of the Enigma machine is that:

**Encryption and decryption are identical operations.**

This works because the reflector makes the entire electrical path reversible.

For example:

typescript

```typescript
const encrypted = machine.encrypt("HELLO");
const decrypted = decryptMachine.encrypt(encrypted);
```

Both machines must have identical:

- Rotor selection and order.
- Initial rotor positions.
- Ring settings.
- Reflector.
- Plugboard configuration.

## 4\. Important limitation

The implementation above is an educational simulation, not a historically accurate Enigma emulator.

In particular, it simplifies rotor stepping and doesn't implement:

- Double-stepping behavior.
- Ring settings.
- Plugboard connections.
- Configurable reflectors.

If you're building a proper Enigma simulator, I'd recommend implementing the **historical Enigma I**, including its authentic
rotor stepping mechanism.

One important note: Enigma is a historical cipher and should not be used for modern security or protecting sensitive
information.
