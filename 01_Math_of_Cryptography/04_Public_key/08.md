The security of the RSA cryptosystem relies heavily on the mathematical difficulty of factoring the product of two large
prime numbers. However, weaknesses can arise from implementation errors, mathematical shortcuts, or poor key management.

---

### Major Types of Attacks on RSA

#### 1. Mathematical and Factoring Attacks

- **Prime Factorization:** RSA's core security depends on the assumption that factoring a very large modulus $n$ (where
  $n = p \times q$) into its original prime components ($p$ and $q$) is computationally infeasible. If an attacker can factor
  $n$, they can easily calculate the private key.
- **Low Public Exponent Attacks:** If a small public exponent (like $e = 3$) is used along with small plaintexts, and the
  message is not properly padded, algebraic shortcuts can allow attackers to recover the original message directly from the
  ciphertext.
- **Common Modulus Attack:** If the same modulus $n$ is shared among multiple users or entities with different public
  exponents, an attacker who intercepts ciphertexts of the same message sent to different users can recover the plaintext
  without knowing the private key.

#### 2. Implementation and Padding Attacks

- **Chosen-Ciphertext Attacks (CCA) & Bleichenbacher’s Attack:** Older padding schemes (like PKCS#1 v1.5) can leak
  information if an application returns distinct error messages depending on whether padding validation succeeded or failed.
  By sending manipulated ciphertexts and analyzing the server's error responses (acting as an "oracle"), an attacker can
  eventually decrypt intercepted messages.
- **Timing Attacks:** This is a side-channel attack where an adversary measures the exact amount of time a hardware device or
  server takes to perform decryption or signing. Because operations like modular exponentiation can take varying times based
  on the bits of the private key, precise measurements can help guess the private key.
- **Power Analysis Attacks:** Similar to timing attacks, these measure power consumption fluctuations on a physical device
  (like a smart card or cryptographic chip) during computation to extract secret key material.

#### 3. Key Generation Flaws

- **Weak Random Number Generators (RNG):** If the pseudo-random number generator used to pick the prime numbers $p$ and $q$
  is predictable or uses insufficient entropy, an attacker can reproduce the key generation process and compute the private
  key.

---

### Prevention and Mitigation Strategies

- **Use Robust Key Lengths:** Avoid outdated key sizes like 1024-bit. Standard security practices dictate a **minimum of 2048
  bits** for RSA keys, with 4096 bits used for long-term high-security requirements.
- **Implement Strong Padding (OAEP):** Always use **Optimal Asymmetric Encryption Padding (OAEP)** instead of older,
  vulnerable padding formats. OAEP introduces randomization to the encryption process, neutralizing mathematical shortcuts
  and chosen-ciphertext attacks.
- **Constant-Time Implementations:** To mitigate side-channel timing attacks, cryptographic libraries must be written to
  execute in "constant time"—meaning operations take the exact same amount of time regardless of the key or input values.
- **RSA Blinding:** To stop timing and power analysis attacks during decryption, implementations can use _blinding_. This
  multiplies the ciphertext by a random value before performing the private-key operation and divides it out afterward,
  rendering execution time independent of the key bits.
- **Handle Errors Uniformly:** Prevent padding oracle attacks by ensuring servers return generic, uniform error messages for
  any decryption or unpadding failure, without revealing _why_ the failure happened.
- **Use Cryptographically Secure RNGs (CSPRNG):** Ensure that prime numbers are generated using robust, thoroughly audited
  random number generators with plenty of system entropy.
